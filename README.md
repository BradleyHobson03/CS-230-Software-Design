# CS 230 Software Design

## The Gaming Room Project

The client for this project was The Gaming Room, a company that wanted to expand its game, Draw It or Lose It, from an existing Android application to a web-based environment that could support multiple operating systems and devices. The software needed to support multiple games, teams, and players while making sure names remained unique. The system also needed to be scalable, secure, and accessible from different platforms.

One thing I did particularly well was organizing the software requirements and comparing different operating platforms before making a recommendation. I was able to look at areas such as memory management, storage, security, networking, and system architecture and explain how those areas affected the final design.

Working through the software design document was helpful because it forced me to think about the structure of the application before focusing on the code. By identifying the classes, relationships, constraints, and platform requirements first, I had a clearer picture of how the program should work and how the different parts of the system fit together.

If I could revise one part of my work, I would improve some of the technical explanations in the design document. I would make the comparisons between operating platforms more concise and make the final recommendation easier to identify. This would help both technical and nontechnical readers understand why the selected platform was the best choice.

I interpreted the user's needs by identifying the main requirements from The Gaming Room, including support for multiple games, teams, players, and devices. I also considered the need for unique names, scalability, security, and compatibility across platforms. Considering the user's needs is important because the goal of software design is not just to create working code, but to create a system that solves the client's actual problem.

My approach to software design is to first understand the requirements and constraints, then break the system into smaller components. I use object-oriented design to identify classes and relationships, and I compare different technical options before choosing an architecture. In future projects, I would continue using design documents, UML diagrams, platform comparisons, and requirement analysis before beginning development because these tools help reduce mistakes and make implementation easier.
